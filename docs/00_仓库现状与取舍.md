# 一、文档 vs 代码：逐条裁决

原则：文档是**设计意图**的存档，不是法律。下面每条都给「谁更好 + 为什么 + 建议动作」。
标 ✅ 的可直接按代码走（改文档即可）；标 ⚠️ 的需要改代码；标 ❓ 的需要你拍板。

## 1.2 文档更好 —— 应该改代码（8 条）

| # | 分歧 | 文档 | 代码 | 为什么文档对 |
|---|---|---|---|---|
| 13 | 逾期边界 | `now >= end_time` 即逾期，且注明"不允许两种写法并存" | `now > end_time`（前后端三处一致） | 到点就算逾期才符合直觉；现在到期那一分钟全系统显示"请假中"，答辩演示卡在边界上会很尴尬 |
| 14 | 材料预览 | 图片直看、**PDF 用 iframe/新窗口**，明确说"这是后台相比小程序的价值" | 非图片一律 `preventDefault()`，改成"演示环境无附件" | 这是后台唯一做得到、小程序做不到的事，主动砍掉等于放弃一半卖点 |
| 15 | 列表分页 | DB 分页，`total` 用于翻页 | 前端 `size=200` + 后端内存切片 | 数据一涨就静默少一半，而且没有任何翻页入口，用户根本不知道少了 |
| 16 | 提交幂等/并发 | `02 §18.1` 要求提交时锁学生行 | 只有 `selectCount` 查重叠 | 这是**唯一真实的并发缺口**：两个请求同时通过检查就会写出两条重叠申请。其他场景用条件 UPDATE 已经够了 |
| 17 | `/auth/me` | 要返回 `studentProfile`（学号/班级/辅导员） | 只返回账号基本信息 | 前端"我的"页为了拿班级要多发一次请求；首页已经拼好了这些字段，me 里没有是遗漏 |
| 18 | 改密码 | `PUT /auth/password` | 端点不存在 | 学生/教师改密码只能找管理员重置，这在答辩时会被问"用户自己怎么改" |
| 19 | 模拟定位 | D-07 要求演示时能用模拟位置 | 配置键不在任何 seed 里，默认关闭；后台也加不了（改配置接口对未知 key 返回 404） | 演示路径直接断了。补一条 seed 就行，成本极低 |
| 20 | 教师"进行中" | 应该是请假中 + 逾期 | `status=ACTIVE` 把"待开始"也算进来 | 待开始的假还没开始，算进"进行中"会让教师误判在校人数 |

## 1.4 一句话总结

- **代码胜在工程判断**：目录结构、分层粒度、组件拆分、存储选择——这些都比你当初写的规划稿更成熟。
- **文档胜在业务边界**：逾期怎么算、材料能不能看、提交要不要防并发——这些是"产品应该怎样"，代码为了省事绕过去了。
- **13 处文档互相矛盾**才是真麻烦：同一件事 01/02/03 三个答案，改代码前必须先裁决（见审计报告 C 类）。

# 四、如果只做一件事

**先清理仓库，再裁决文档。**

理由：`dsh-experts/`、`design/`、`outputs/`、三个 `.tmp*` 混在根目录里，会让你每次找文件都多花时间，也容易误改淘汰版本。清理是 10 分钟的事，且零风险（都在 git 里或可再生产）。

顺序建议：
1. **10 分钟**：删 `.tmp*`、`outputs/`；`git rm --cached project.private.config.json`；`.gitignore` 补 `.tmp_probe/`
2. **10 分钟**：`design/` → `archive/design/`；`dsh-experts/` 移出仓库；给 `archive/` 加 `README.md`
3. **30 分钟**：`scripts/` 建 `archive/` 子目录，把 16 个一次性脚本挪进去（不删，留着可回溯）
4. **半天**：裁决 13 处文档矛盾（审计报告 C 类），同步 01/02/03
5. **1 天**：修 7 个 P0
