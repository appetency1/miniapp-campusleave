# 学生端 H5 体验与交互规范 V1.0

> 依赖 `01-visual-direction.md`（下称「视觉」，尺寸唯一来源）与 `conclusioV1.0（stu）.md`（下称「业务」）。视口 375×812 = 状态栏 44 + 导航 44 + 内容 + tabBar 50。
> 可用内容高：tab 页 `674`；push 页 `724`；push 页 + 操作栏 `656`。所有间距取 4pt 标尺，不新增 token。
## A. 全局交互规则
### A1 页面栈模型
```text
栈底（tabBar，互不销毁，各自保留滚动位置 + 筛选态）
  S1 首页 ── S3 记录 ── S7 消息 ── S9 我的
push（覆盖全屏，隐藏 tabBar）
  S1 → S2 申请请假 →（提交成功 replace）→ S4 详情
  S3 → S4 详情 → S5 续假 / S6 定位销假
  S7 → S8 消息详情 →（跨模块）→ S4 详情
```
- 切 tab：**保留**滚动位置、筛选选中项与列表数据；不重置、不重新请求（超过 60s 或数据被操作变更才重拉）。
- 返回：导航 chevron / 系统手势 / Android 物理返回统一 pop 一层；栈底页返回由外壳吞掉。
- `replace`：S2 提交成功后以 S4 替换 S2，返回直达 S1，不回到已提交表单。
- 脏表单：S2/S5 有改动时返回弹「放弃本次填写？」；无改动直接返回。
- S5 提交成功 → pop 回 S4（原地出现「续假待审批」小徽章）；S6 成功 → pop 回 S4 并刷新为 COMPLETED。禁止成功后跳新详情页。

### A3 滚动 / 吸顶 / 底部
- 单轴纵向滚动，不横向滚动（筛选栏除外）。吸顶仅 S3 筛选栏（48，滚动 >0 时底边 1px `#E2E7EF`）；S4 结论区随滚动。
- 底部操作栏 `fixed` 高 68 + safe-area，仅 S2/S4/S5/S6 有；存在时滚动区 `padding-bottom 80`。
- **下拉刷新不做**（本地演示数据，且与筛选栏吸顶手势冲突）。刷新点 = 进入页面 / 操作成功后局部更新；失败给「重试」。
- 首页 484 < 674 不滚动；详情 ≈1120，滚动 1.7 屏。
- **断点**（视觉 §4）：`≥414` 页面边距 24，内容变宽、字号与行高不变；`≤360` 场景双卡改纵向堆叠（各满宽 ×104，本轮 S2 场景区 104→218），S9 统计 4 列改 2×2（+88），筛选栏不改（继续横滚）。其余屏只做流式放宽，不重排信息层级。
### A4 全局反馈
| 类型 | 触发 | 规格 |
|---|---|---|
| Toast | 所有变更操作结果 | 视觉 6.9，2000ms，居底 120，`role=status aria-live=polite`，不抢焦点 |
| Loading（按钮） | 提交/撤回/取消/销假/续假 | 文字换 20px 白环，宽高不变，立即 disabled；同操作 2s 内重复点击忽略；6s 超时 → Toast「请求超时，请重试」+ 恢复 |
| 骨架屏 | 列表/详情首次进入 | 300ms 内返回不显示（防闪）；>300ms 显示，最多 3 张 |
| 错误态 | 请求失败 | 视觉 6.7；列表失败保留 tabBar + 筛选栏，不整页替换 |
| 二次确认 | 撤回 / 取消 / 确认结束 / 放弃填写 | 视觉 6.9 弹窗，遮罩点击 = 取消 |

### A6 输入与键盘
- S2/S5 的 textarea 聚焦时，底部操作栏整体 `translateY(100%)` 隐藏（不随键盘上移，避免与键盘双占位），失焦 120ms 恢复；滚动区 `padding-bottom` 同步降为 20。用 `visualViewport` 高度差判断。
- textarea `min-height 96`，随内容自适应至 200 后内部滚动；上限 **200 字**（业务未限，取 200 覆盖正常描述）；计数 12/16·500 `tabular-nums`。
- 输入行上限：去向 50、联系电话 11。所有 `input` 不 autofocus（避免首屏弹键盘）。
- 校验时机：**失焦 + 提交**，不做输入中实时红框（视觉 6.6）；错误行下方 12/16 `#C0281E`，并置 `aria-invalid`。
### A7 无障碍
- 焦点顺序 = DOM 顺序 = 视觉顺序，不用 `tabindex` 重排；弹窗打开焦点移入「取消」，`aria-modal` + 焦点环闭，关闭后焦点回触发按钮。
- 场景双卡 = 原生 `input[type=radio]` + `sr-only` 隐藏、`<label>` 包整卡、容器 `role=radiogroup` + `aria-labelledby`；roving tabindex，`←→↑↓` 切换、`Space/Enter` 选中。
- 语义不靠颜色：徽章有文字，逾期有 ⚠ + 「逾期」，定位失败有图标 + 文案 + 色。
- tabBar `role=tablist`，激活项 `aria-selected=true`；消息项 `aria-label="消息，3 条未读"`；时间轴用 `<ol>`，节点 `aria-label="审批，10.16 14:20 已完成"`。
- 触达 ≥44：文字按钮热区 44；筛选项 `min-width 44`（item 间距 20、首尾 20，热区由 min-width 兜底）；消息「全部已读」热区 44。
- 200% 字体缩放：label-value 行允许换行加高，value 不做单行省略；对比度全依赖视觉 §2 token，`#A9B2C2` `#4E82DB` 禁承载文字；`prefers-reduced-motion` 按视觉 §9 降级。
### A8 状态与时间计算（前端唯一口径）
- `overdue = status===IN_PROGRESS && now > effectiveEndTime`；续假待审批期间 `effectiveEndTime = 原结束时间`（业务 §32）。
- `APPROVED && now >= start` → 按 IN_PROGRESS 渲染（业务 §20，不依赖定时写库）。
- 首页选卡：只 1 张，优先级 `IN_PROGRESS（含逾期）> APPROVED > PENDING > 最近一条终态`。
- 记录排序：逾期置顶 → 进行中 → 待审批 → 已通过 → 其余终态；组内按开始时间倒序。

### S3 请假记录（tab）
**目的**：追踪全部申请，按状态定向。**入口→出口**：tab；卡片 → S4；空态按钮 → S1。

| 区块 | 高 | 要点 |
|---|---|---|
| 筛选栏（吸顶） | 48 | 8 项下划线文字 tab，横向滚动；选中 15/600 `#121A26` + 2px `#2563C9` 下划线（线宽 = 文字宽），未选 15/500 `#5A6577`；item 间距 20、首尾 padding 20 对齐页边距；左右 8px `#F5F7FA→透明` 渐隐**仅在可滚方向出现**（滚到右端即撤右遮罩） |
| 列表上内距 | 12 | 卡片间 `gap 10` |
| 申请卡 | 168 / 跨天 192 / REJECTED 188 | 复用视觉 6.4，整卡热区 |
| 滚动区 padding-bottom | 12 | 无操作栏 |
**筛选映射（FE 照此实现）**：全部=所有｜待审批=`PENDING`｜已通过=`APPROVED`｜请假中=`IN_PROGRESS`（含逾期）｜已驳回=`REJECTED`｜已销假=`COMPLETED`｜已取消=`CANCELLED`｜已撤回=`WITHDRAWN`。
**筛选栏铁律**：未选中态一律中性灰，**禁止使用任何状态色**（视觉 P2：一屏高饱和色块 ≤2，语义识别只能靠卡片内徽章，不能靠筛选栏）。
**裁决 2**：**增加第 8 项「已撤回」**。① 7 项本身已超宽（≈550px > 335），加 1 项不新增滚动成本；② 筛选项名必须与徽章文案一一对应，把 `WITHDRAWN` 并入「已取消」会让结果与标签不符；③ 撤回是学生主动、可回溯的动作，有检索意图，排末位不干扰主路径。选中项 `scrollIntoView({inline:'center'})`，容器左右各 8px `#F5F7FA` 渐隐遮罩提示可滚。
**状态矩阵**：默认「全部」；筛选无结果 → 列表内空态「该状态下暂无记录」+ 文字按钮「查看全部」；切换筛选 → 列表 `opacity` 200ms 淡入，不整页 loading，筛选栏不重建；切 tab 回来保留上次筛选。
**边界**：驳回原因首行单行省略（详情看全）；>30 条按 20 条/页滚动加载（演示数据不足则不实现）。

### S6 离校定位销假（push）
**目的**：一次定位校验完成销假，失败绝不自动标记完成。**入口→出口**：S4（IN_PROGRESS + OFF_CAMPUS）→ 本屏；成功/失败均可返回 S4（成功时刷新 COMPLETED）。

## F. 交互验收清单（FE 自检 15 项）
1. S3 的 8 项筛选映射与 S4 的徽章/结论/时间轴/操作栏组合逐一对得上，「已通过」不得包含 `IN_PROGRESS`。
2. `PENDING` 详情底部只有一个满宽描边按钮，点击出现二次确认，取消后无任何数据变化。
3. `APPROVED` 详情主操作为描边危险「取消申请」，确认文案含「不会生效」，确认后操作栏消失。
4. `IN_PROGRESS` 详情主按钮随 `scene` 在「确认结束」/「返校定位并销假」间切换，次按钮恒为「申请续假」。
5. 逾期详情必同时出现 40 高红色提示条 + 描边「⚠ 逾期」徽章 + 主按钮上方两个文字按钮。
6. 定位失败（范围外/权限/超时）返回 S4 时状态仍为 `IN_PROGRESS`，任何失败路径都不得写入 `COMPLETED`。
7. S5 已有待审批续假时整屏只读且主按钮为 disabled「续假待审批中」，无法进入时间选择。
8. 续假待审批期间 S4 结束时间显示原值；若已过期仍展示逾期标记。
9. S2 场景与类型默认均未选中；未选状态点提交时滚到场景卡并显示「请选择请假场景」。
10. S2 结束时间 picker 最小可选值 = 开始时间 +10 分钟，跨天时行下出现总时长说明。
11. 所有变更操作点击后 100ms 内进入 loading + disabled，2 秒内重复点击不产生第二条记录。
12. S2/S5 有改动时返回弹「放弃本次填写？」，无改动直接返回。
13. S2 提交成功 `replace` 到 S4，从 S4 返回直达 S1（不回表单），且 S1/S3 数据已更新。
14. 场景双卡只有 1 个 Tab 停靠位、方向键可切换且始终单选；8 项筛选栏可横滚且选中项自动居中。
15. S9「未读红点提醒」行在开关开/关两种状态下高度均为 72、副文案常驻（无布局跳动），切换只让 tabBar 未读 pill 与红点消失/恢复，消息列表与已读逻辑不变，刷新后仍为关闭态（`cl_settings.badgeEnabled=false`）；筛选栏任何未选中项都不出现状态色。
