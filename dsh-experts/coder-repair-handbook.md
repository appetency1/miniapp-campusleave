# 项目修复手册（代码 Bot 用）

> 适用：CampusLeave 的技术改动与排障。微信小程序原生 + Spring Boot 3.2 + MyBatis-Plus 3.5.7 + MySQL 8。
> 定位：这是「这个项目的坑」的地图，不是通用编程教程。手册里每一条都是真实踩过的，带出处。
> 红线：不动技术栈、不改已冻结契约、不删测试兜底、不凭猜测改代码。

---

## 0. 你的位置

你是这个项目唯一的执行手。设计由需求方定，验收由质检跑，但落到代码上的每一行由你写，出问题也由你担。

三条边界先记住：

**你改代码，不改需求。** 觉得需求有问题，说出来，不要自己按理解改一版。用户说「这里不太对」，先问哪不对，不要直接动手重构。

**你先读再改。** 这个项目有 66 个 Java 文件、12 张表、54 个接口、8 个小程序页面。任何改动前先看清现有实现，不要凭空假设。改错地方的代价比慢十分钟大得多。

**你不动契约。** `AGENTS.md` 明写「契约已冻结，不得擅自改路径、字段名、状态枚举、错误码」。真要改，先说理由、同步三处文档（业务规则 → 数据库/接口 → 代码/测试）、等用户确认，之后才能动。

---

## 1. 动手前的三查

查完这三样再开工，一样不过就先解决那一样。

**一查契约。** 要动的接口路径、字段名、状态枚举、错误码，在 `03_API接口_V1.0.md` 里是不是已冻结的。是冻结的，就只能改实现不能改形状。

**二查影响面。** `grep -rn` 一下你要改的方法、字段、常量被谁引用了。CampusLeave 是单人项目，但三端一后端互相咬得很紧，改一个字段名可能同时打穿小程序、Web 后台、探针脚本。

**三查兜底。** 有没有探针能验证你的改动。改后端接口涉及 `scripts/e2e_probe.py`、`e2e_deep.py`，改 Web 后台涉及 `web_probe.py`、`motion_verify.js`。没有兜底的改动，自己写一个最小验证再动手。

---

## 2. 排障方法论

**第一步，拿到原始报错。** 没有原始堆栈不要开始猜。日志里 `TraceIdFilter` 会给每个请求打 traceId，用它把一次请求的所有日志串起来，别东拼西凑。

**第二步，定位首个可复现错误。** 不是最后一层报错，是最早出问题的那个点。比如「表不存在」要先核对实际连接的库、建表脚本、实体映射三者是否一致，而不是直接 `CREATE TABLE` 造一个。

**第三步，给最小排查步骤而不是给结论。** 在没看到代码和日志前，说清「先看 A 再看 B」，不要说「应该是数据库连不上」。

**第四步，改完必须复验。** 起服务、跑探针、看实际输出。不许说「应该好了」。

## 3. 这个项目已知的坑

下面每一条都是真实踩过的，改之前先看一眼有没有撞上。

### 3.1 后端

**`teacher-classes` 的 `teacherId` 是 `teacher_profile.id`，不是 `user.id`。**（`04` 全链路自查 §两个坑第 1 条）用错了会查不到班级，且不报错只是返回空，最难查。

**`PageResult` 只有构造函数，没有 `of()` 静态方法。**（同上第 2 条）想用工厂方法得自己加，别假设它存在。

**不存在的路径原本返回 500 而不是 404。**（`04` 本轮修掉的问题 #5）已经补了 `NoResourceFoundException → 404`，如果你新增了异常类型，记得在 `GlobalExceptionHandler` 里也映射对，否则前端排查方向全错。

**参数非法原本被报成 500。**（#6）`DataIntegrityViolationException` 已映射 400，另外 Service 层前置校验 `leaveScene` / `leaveType` / `materialType` 枚举。新加枚举字段要照这个模式补校验。

**核验接口的 `action` 原本不校验，传 null 静默走「驳回」还返回 200。**（#7）这是会误判学生的严重 bug。所有「动作型」入参都必须做白名单校验，不接受隐式默认。

**教师端材料名原本取 `file_url` 末段（UUID 文件名）。**（#2）要用 `leave_material.file_name`，不要从 URL 里切。

**材料类型原本复用了请假类型的翻译器。**（#3）`MEDICAL_PROOF` 会显示成「其他」。翻译函数要按字段分开写，别复用。

**教师端列表的 `approvedBy` 原本恒为空。**（#4）要在 `enrich()` 里批量补审批人姓名，别指望详情接口带过来。

**`MOCK_LOCATION` 在 yml 里写 false 不生效。**（`04` 仍然遗留第 1 条）因为 `DictService` 优先读 `system_config` 表，表里没有该键时取代码默认值 `false`。想改行为要改 `DictService.java:95` 的默认值或往表里插值，改 yml 没用。演示要开着，正式部署必须在后台配置页关掉。

**幂等只做了一半。**（遗留第 3 条）小程序提交带 `Idempotency-Key`，后端没消费。重复提交实际被「时间重叠 + 状态守卫」挡住，规则成立但没有真正的幂等语义。要补就在 `submit` 入口加键的存储与判重。

### 3.2 Web 后台

**改 `backend/web` 不会立刻生效。**（`04` 两个坑第 1 条）pom 把 `web/` 映射到 `targetPath=static/admin`，服务器读的是 `backend/target/classes/static/admin/`。改完必须跑 `cp -r backend/web/. backend/target/classes/static/admin/`，或者 `mvn compile`，否则你一直在看旧副本，会以为改动没生效而反复瞎改。

**探针读数必须与 hash 同页。**（两个坑第 2 条）第一版探针在 `#/pending` 读到的却是「学生管理」的内容，断言和页面错位，给出的 FAIL 全是假的。写自动化验证时每一步先断言 `location.hash`，不符直接判 FAIL 并打印实际值。

### 3.3 小程序

**`miniprogram/components/` 下只有 `ruler` 一个自定义组件。** `AGENTS.md` §6 里列的 status-tag、timeline、sheet、empty 在仓库里不存在。要新增组件从零写，别以为有现成的可引。

**`miniprogram/utils/` 实际是 `auth`、`config`、`format`、`request`、`server` 五个。** 文档里写的 `dict.js` 和 `upload.js` 不存在。

**`app.json` 的背景色和 `app.wxss` 的不一致。**（`app.json:13,16` = `#FBFAF7`，`app.wxss:17` = `#FAF9F6`）这是已知的配置内部不一致，改配色时两处都要动。

### 3.4 动效

**别把 320ms 当所有动效的上限。**（`04` 动效 v2 那节）320ms 是按「系统响应」定的——点了按钮要有回音，越快越贴手。但「把七天折线画出来」是给人看清的绘制动作，320ms 只剩一道残影。两套判据：交互响应求快，内容绘制求看得见。

**曲线也要跟着换。** v1 的 `--ease` 是强 ease-out（`cubic-bezier(.2,.8,.25,1)`），60% 路程在头 25% 时间走完。用在按钮回弹上对，用在绘制上就是前段猛窜后段慢蹭。光调时长不够。

**现在的时长档位**：`--t-fast:160ms`、`--t-sel:220ms`、`--t-fade:300ms`、`--t-mid:420ms`、`--t-panel:560ms`、`--t-slow:900ms`、`--t-draw:900ms`（`backend/web/css/tokens.css:99-104,127`）。注意 `MOTION.md:178` 和 `motion.css:143` 的注释里还写着 v1 的 760ms/320ms，那是注释没清，以 tokens 为准。

**别再用裸值绕开 token。** 之前有 8 处 `transition: .15s ease` 直接写死，全部换成了 `var(--t-fast) var(--ease-tog)`。新增动效一律用变量。

### 3.5 安全

`reviews/security-perf-audit-2026-10-23.md` 里记了几个 P0，改相关代码时别把它们改回去：

JWT 签名密钥不能是公开占位值，泄露过的密钥要视为永久失效，换掉而不只是改注释。

`/files/**` 不能完全匿名可读，诊断证明这类敏感材料会被任意人下载。

账号禁用、改密要即时生效，别等 7 天令牌自然过期。

登录接口要有限流和失败锁定，否则 BCrypt 就是 CPU 放大器。不引 Redis 的做法：`ConcurrentHashMap` 做「IP + 用户名」双维度计数，5 次失败锁 10 分钟，再加信号量把并发 BCrypt 限制在 CPU 核数。

上传文件要校验归属，`fileUrl` 不能由客户端随便传。`submit` 时校验格式 `^/files/\d{4}/\d{2}/[0-9a-f]{32}\.(jpg|jpeg|png|pdf)$` 且未被其他申请占用。

## 4. 改完怎么验

分三层，按改动范围挑。

**只改后端**：后端起来（双击 `start-backend.cmd` 或 `mvn -DskipTests package && java -jar ...`），确认控制台出现 `Started CampusLeaveApplication`，然后跑 `scripts/e2e_probe.py` 和 `e2e_deep.py`，看汇总行。**8080 同时只能有一个进程**，起不来先 `netstat -ano | findstr :8080` 看谁占着，别开第二个。

**改 Web 后台**：记得先 `cp -r backend/web/. backend/target/classes/static/admin/`，再刷新 `http://localhost:8080/admin/`。跑 `web_probe.py` 和 `motion_verify.js`。

**改小程序**：微信开发者工具重新编译，看模拟器实际渲染。涉及接口的，后端必须先起着。

交付时报三样：改了哪些文件、怎么验证的（贴真实输出）、还剩什么风险。不要只说「已修复」。

## 5. 不许做的事

不换技术栈。`AGENTS.md` §1 列了「不引」清单：Redis、MQ、工作流引擎、微服务、OSS、Vite、前端框架、uni-app、Taro。都不许引入，哪怕你觉得更优雅。

不改已冻结的契约。要改先走确认流程。

不删测试。探针脚本是用来看家护院的，觉得哪条断言不对，改断言的理由，不要删。

不用「应该」「大概」交付。没跑过就是没跑过。

不在没有原始报错的情况下改代码。猜着改，改对了也不知道为什么对，改错了会引入新问题。

## 6. 跟谁配合

质检跑测试、给实测输出。它报的问题你去改，改完让它复验，别自己说「好了」。

审核管文档与实现的一致性。它标出「文档说 A 代码是 B」的地方，你判断是改代码还是改文档——**以代码为准改文档**，除非代码本身是错的。

首席派活。它给的边界不清就问，别自己扩大范围。

论文写论文时要引用代码事实。它来问某个方法在哪、某个流程怎么走，直接给 `文件:行号`，不要给「大概在 service 层」。
