# MOTION.md —— 校园请假后台 · 动效语言 v2

> 适用：`backend/web/`（原生 JS + 原生 CSS，无框架 / 无构建 / 无依赖）
> 定位：本文件只给**设计决策 + 变量表 + 编排参数**。所有数值可直接抄进 CSS，不含实现代码。
> 气质基准：**像纸、像文具、像印刷品**。动效不是装饰，是"纸面上的一次落墨 / 一次翻页 / 一次盖章"。

## 0.0 v2 修订（2026-10-22 21:00）—— 整套时长按"人眼能看见"重算

**触发**：v1 上线后用户反馈"**一眨眼的事，根本看不清**"，先点名概览的折线图和轮盘，
随后指出"其他的那些也是"。也就是说问题不在个别编排，在**整套时长体系**。

**v1 错在哪**：v1 把"单次动作 ≤ 320ms"当硬上限。这个上限是按**系统响应**定的
（点了按钮要立刻有回音），但它被套用到了所有地方，包括"把七天折线画出来"这种
**给人看**的绘制动作。两者不是一回事：

| | 交互响应 | 内容绘制 |
|---|---|---|
| 目的 | 告诉系统"我收到了" | 让人**看清**发生了什么 |
| 判据 | 越快越贴手（慢了会觉得卡） | 越慢越看得见（快了等于没做） |
| 320ms | 合适 | **太赶**——只剩一道残影 |

还有一层：v1 用的 `--ease` = `cubic-bezier(.2,.8,.25,1)` 是**强 ease-out**，
60% 的路程在头 25% 的时间里走完。这条曲线用在按钮回弹上是对的（快起慢收），
用在"画笔"上就成了**前段猛地窜出来、后段慢慢蹭** —— 这正是"看着太快"的根因。
所以光把时长调长不够，**曲线也得换**。

**v2 的三条决定**：

1. **时长阶梯整体上调**，并把"内容绘制"从交互档里拆出来单独一档：

   | 档 | 变量 | v1 | **v2** | 语义 |
   |---|---|---|---|---|
   | 微反馈 | `--t-fast` | 120ms | **160ms** | hover / 按下 / 焦点环 / 禁用态。再慢会"粘"，这类不能拖 |
   | 状态切换 | `--t-sel` | 120ms | **220ms** | 底色、边框色等可逆状态，来去同速 |
   | 内容淡入 | `--t-fade` | 120ms | **300ms** | 一块内容从无到有（页根、`.detail` 重新落墨） |
   | 元素进出 | `--t-mid` | 180ms | **420ms** | 列表项入场、toast、页头落墨、下拉展开 |
   | 面板级 | `--t-panel` | 240ms | **560ms** | 抽屉、遮罩 |
   | 数据绘制 | `--t-slow` / `--t-draw` | 320ms | **900ms** | 折线描边、环形分段、数字滚动 |

   硬上限从 320ms 提到 **1.2s**（只用于数据绘制），其余档位不超过 560ms。
   代价是"页面拼装完成"要 1 秒左右；换来的是每一步都看得见 —— 这是这次修订的唯一取舍。

2. **错落间隔 24ms → 70ms**。24ms 在 180ms 的单项时长里根本看不出来，
   那不是错落，那是同时出现。70ms × 6 步 + 420ms 单项 = 840ms，一屏列表能看清是"一条条落位"。

3. **新增第 4 条曲线 `--ease-draw` = `cubic-bezier(.32,0,.18,1)`**，
   专门给数据绘制用：起手慢、中段匀、收尾缓，读起来像笔在纸上走。
   `--ease` 仍留给按钮、页头这类入场。

**v1 → v2 数值对照（§4 各节的编排一律按这张表取值）**

| 场景 | v1 | **v2** |
|---|---|---|
| 页根淡入 | 120ms | **300ms** |
| 页头落墨 | 180ms | **420ms** |
| 列表项入场 | 180ms | **420ms** |
| 列表错落间隔 / 步数 | 24ms / 5 步 | **70ms / 6 步** |
| 抽屉 + 遮罩 | 240ms | **560ms** |
| toast 进出 | 180ms | **420ms** |
| 下拉展开 | 120ms | **220ms** |
| 数字滚动 | 320ms | **900ms** |
| 折线描边 | 320ms | **900ms** |
| 面积上彩 | 240ms | **700ms** |
| 折线数据点 | 120ms | **260ms** |
| 环形扇区单段 / 错落 | 180ms / 24ms | **620ms / 150ms** |
| 骨架呼吸周期 | 1.8s | **2.4s** |
| 状态点脉动周期 | 1.2s | **1.5s** |
| hover / 状态色 | 120ms | **160ms / 220ms** |

**时长改长后必须同步改的定时器**（不改就会把动画砍掉半截，这是本轮最容易漏的地方）：

| 位置 | 原值 | 新值 | 不改会怎样 |
|---|---|---|---|
| `ui.js` 抽屉关闭后移除节点 | 260ms | **620ms** | 面板滑到一半被抽走 |
| `motion.js` 列表门控兜底摘类 | 500ms | **1400ms** | 后面几行永远出不来 |
| `ui.js` toast 移除 | 2100ms | **2300ms** | 淡出被截断 |
| `motion.js` flash toast 延迟 | 320ms | **600ms** | 与页面入场抢注意力 |

**验收方式变了**：v1 只能看最终截图（终态永远一样，看不出快慢）。
v2 增加 `scripts/motion_frames.js` —— 把门控拆掉重放一次，按 120/320/560/820/1200ms
逐帧截图，**用画面证明节奏**。实测：120ms 时数字停在 7/2/1/1、折线只起笔、轮盘几乎空白；
320ms 画到八成；560ms 面积洇开；820ms 数据点落位。

## 0.0.1 v2.1 修订（2026-10-23）—— 导航切换的连续性

**触发**：用户反馈"切换导航页的时候总感觉有点生硬"。

**诊断**（不是"没有动画"，是"动画没接上"）：v2 里页根淡入 + 页头位移都有，但两处断了 ——
① **主体内容是瞬间出现的**：`.page` 的直接子级（`.wb` / `.md` / `.ah-*`）没有入场，
壳在淡入、内容却"啪"一下满格，读感就是"生硬"；
② **侧栏选中态是硬切**：`renderNav()` 每次路由都重建 nav，墨线由每个
`.nav-item.is-on::before` 各画一条，切导航时"啪"地换位置，没有连续性。

**v2.1 做了三件事**

| # | 改动 | 参数 | 为什么 |
|---|---|---|---|
| 1 | 页面**内容根**淡入 | `opacity .45→1`，`--t-mid`(420ms)，delay `--m-delay-content`(80ms) | 壳先亮、内容后定 —— 内容是"落定"不是"亮起"，两者的先后本身就是层次 |
| 1b | 页根起点 `opacity: 0` → `var(--m-page-from)`(.18) | — | 从 0 起时第一帧接近全白，纸底整片透出来，读感是"闪"不是"过渡" |
| 2 | 侧栏墨线改为**一条常驻 rail** | `transform/height` 过渡 `--t-mid`(420ms) `--ease` | 从旧项"滑"到新项，是导航切换里最明显的连续性线索 |
| 3 | 面包屑换文案时淡入 | `opacity .45→1`，`--t-sel`(220ms) | 面包屑是"我在哪"的唯一指示，硬切会像弹窗闪一下 |

**两个必须记住的实现约束**（都写进了代码注释）：

- **内容根绝不能加 transform**。`.md-detail` 里的 `.action-bar` 是 `position: sticky`，
  祖先一旦有 transform，包含块就变了，粘性定位会失效（操作条会跟着页面飘走而不是钉在底部）。
  同理 `.page` 自身绝不能有 transform —— 它是 `height:100%` 的 flex 容器，
  还要承接 `router.js` 里 `scrollMap` 的 `scrollTop` 恢复。**位移只给 `.page-head`。**
- **rail 必须在 nav 重建时存活**。`renderNav()` 原本是 `nav.innerHTML = ''`，
  会把 rail 一起清掉；改成只删非 rail 子节点。两个附带坑：
  ① `nav.children` 是**活集合**，边遍历边 `remove()` 会漏删最后一个 → 先摊成静态数组；
  ② `insertBefore` 会把节点摘下来再插回去，**正在跑的 CSS transition 会被打断**（墨线会顿一下）
  → 已经在首位就不动它。
  首次落位还要"摘 `.is-set` → 写值 → 强制回流 → 下一帧挂回 `.is-set`"，
  否则墨线会从 `height:0` "长"出来而不是"移"过去。

**面包屑只在文案真的变了时才播**：`crumbs([])` 在路由的 `onBefore` 里会被调用一次清场，
只看容器内容的话"清场"会把签名冲掉，同页重绘（审批后 `rerender`）就会误判成"换了"→ 白闪一次。
所以签名记在 JS 变量里（`crumbSig`），且只在有内容时更新。

**仍然不做**页面退场 / 新旧页交叉淡出：要把 router 改成两段式（等旧页淡出再换 DOM），
会和 `hashchange` 抢时序，连点两次导航可能停在中间页 —— 这个坑比"生硬"更糟。

> 本节取代 §4.1 里"主内容块一律不动"那一条：内容根现在有入场了（只动透明度）。
> §4.1 其余结论（页根只动 opacity、不做退场、入场必须纯 opacity + 布局后位移）仍然有效。

## 0.0.2 曲线会"吃掉"时长（2026-10-23 实测）

v2 把时长整体调长后，导航切换**看起来仍然快**。逐帧取证找到原因：
**前置曲线让长时长变成假长。**

`--ease` = `cubic-bezier(.2,.8,.25,1)`：头 25% 时间走完约 80% 路程。
写 420ms，实际能看见的变化只有约 150ms；后 270ms 只挪 2–3px，人眼察觉不到。
v2.1 的 rail 一开始就是这个问题 —— 72px 的位移，100/300/600ms 三帧几乎一模一样。

**判据（一句话）**：把动画按毫秒切片拍三帧。**如果三帧看不出差别，那时长就是假的。**

**选曲线的规则**（这是本次最值钱的一条）：

| 动的是什么 | 用哪条 | 为什么 |
|---|---|---|
| **两个状态之间的位移**（rail、把手、进度） | `--ease-tog`（对称） | 对称曲线把路程摊到整个时长，才读得出"滑"；前置曲线读作"跳" |
| **内容从无到有**（淡入、落墨） | `--ease-tog`（需要被看见时）或 `--ease`（需要"立刻可读"时） | 前者让淡入真的摊开；后者让内容尽早可读 |
| **数据绘制**（折线、环形、数字） | `--ease-draw` | 起手慢、中段匀、收尾缓，像笔在走 |
| **退场** | `--ease-in` | 加速离开，尽快把注意力还回去 |
| 外壳亮起（页根） | `--ease` | 壳该快点，"快起慢收"在这里是对的 |

**结论**：调时长之前先看曲线。曲线不对，时长调到 1000ms 也还是"一闪"。

## 0.1 落地前必须先知道的 8 个既有事实（已逐文件核对）

这些直接决定动效能不能挂上去，动效方案若无视它们就是白写。

1. **`.tbl tbody tr.is-hover` 永远亮着**：`ui.js:253` 只要有 `onRowClick` 就给每行加 `is-hover` 类，而 `components.css:135` 写的是 `.is-hover` 而不是 `.is-hover:hover` → 表格"悬停底色"目前是常亮的。动效无从谈起，先改成 `:hover`。
2. **`.nav-item.is-on::before` 基础规则不存在**：`layout.css:162` 只在 `<1420` 媒体查询里覆写 `top/bottom`，基础 `::before` 从未定义 → 这条指示器是死规则，侧栏现在没有墨线，只有底色。
3. **`--t-sel: 120ms` 从未被任何选择器引用**（全站只有 `--t-fast / --t-fade / --t-panel / --ease` 被用到）。它是"预留但没接线"的变量。
4. **toast 退场 350ms 已超 320 上限**（`components.css:991`），必须改。
5. **7 处 `transition: .15s ease` 绕过 token**（`admin-home.css:159`、`components.css:883/948`、`layout.css:104/510`、`workbench.css:109/347`），它们既不在阶梯里，也没有用命名曲线。
6. **三处整块重建 DOM**：`router.render()` 换掉整个 `.page`；`pending.js:87 renderList()` 每次点选 `innerHTML=''` 重建左栏；`app.js renderNav()` 在每次审批后（`shell.sync()`）重建整个 nav。→ **任何入场动画都必须有一次性门控**。
7. **`.detail` 已带 `.fade-in` 且从 `opacity:0` 起**（`detail.js:310`、`pending.js:220`、`review.js:194`）→ 点一次左栏，右栏就"白一下再显影"。且 `.fade-in` 是 140ms，比阶梯里的 120 多 20ms。
8. **`ui.skeletonRows` 全站 0 调用**，`.sk` 没有 shimmer；`.ah-donut-svg` 的扇区是 **`fill` 路径（无 stroke）**，所以环形图不能"描边生长"。

## 1. 缓动集（3 条，封顶）

| 变量 | cubic-bezier | 用途 | 为什么是它 |
|---|---|---|---|
| `--ease`（**保留现有**） | `cubic-bezier(.2,.8,.25,1)` | **入场 / 展开**：页根淡入、页头落墨、列表入场、toast 进入、抽屉推入、下拉展开、折线描边、数字滚动 | 强 ease-out：约 60% 的路程在前 25% 时间走完，后段"压住"。读感是"笔尖落纸，然后手停住"，不是"弹到位" |
| `--ease-in`（新增） | `cubic-bezier(.4,0,1,1)` | **退场**：toast 退出、抽屉关闭、遮罩淡出 | 加速离开。退场不该有"优雅收尾"，它应该尽快把注意力还回去 |
| `--ease-tog`（新增） | `cubic-bezier(.4,0,.6,1)` | **状态切换**：hover 底色、边框色、`:disabled` 透明度、扇区分段落墨、`.form-err` 显影、骨架呼吸 | 对称曲线。可逆状态必须"来去同速"，用 `--ease` 会让鼠标移开时出现"先慢后快"的拖尾 |

### 为什么不用 spring（也不用 `linear()` 采样出来的假弹簧）

1. **气质冲突**：overshoot + 回弹是 Material / iOS 的语言（"物体有惯性"）。本产品的隐喻是纸 —— 纸不会冲过头再弹回来。用户在需求里已明确否决"弹簧 overshoot 明显回弹"。
2. **工程代价**：真弹簧要么每帧 JS 驱动（本项目零依赖，得手写一个 60 行的 spring solver），要么用 `linear()` 自定义时间函数 —— 而 `linear()` 需要较新的 Chromium（学校机房常见的旧版 Chrome/Edge 会静默退化成一整段 `ease`，动效直接变形）。`cubic-bezier` 是唯一 100% 安全的选择。
3. **收益为零**：单次 ≤320ms 时，弹簧的两个核心优势（可中断、速度连续）在视觉上不可分辨。花 320ms 以内的钱，买不到弹簧的价值。

## 2. 时长阶梯（6 档，v2）

| 档 | 变量 | 值 | 语义 | 说明 |
|---|---|---|---|---|
| 微反馈 | `--t-fast` | **160ms** | hover / 按下 / 焦点环 / 禁用态透明度 | v1 是 120ms。160ms 仍"贴着光标"，再慢会觉得粘 |
| 状态切换 | `--t-sel` | **220ms** | 底色、边框色、颜色等可逆状态 | v1 是 120ms，与 `--t-fast` 同值；v2 拆开 —— 状态色变化比 hover 底色更值得被看见 |
| 内容淡入 | `--t-fade` | **300ms** | 页根淡入、`.detail` 重新落墨 | v1 是 120ms |
| 元素进出 | `--t-mid` | **420ms** | 列表项入场、toast 进出、页头落墨、下拉展开 | v1 是 180ms |
| 面板级 | `--t-panel` | **560ms** | 抽屉、遮罩 | v1 是 240ms |
| 数据绘制 | `--t-slow` / `--t-draw` | **900ms** | 数字滚动、折线描边 | v1 是 320ms（见 §0.0：内容绘制不能用交互档的量级） |
| — | `--t-draw-area` | **700ms** | 折线面积上彩 | v1 是 240ms |
| — | `--t-draw-seg` | **620ms** | 环形图单段落墨 | v1 是 180ms |

**规则**
- **交互档上限 560ms**（面板级）；**数据绘制档总收尾 ≤ 1.2s**。
  这两个上限性质不同：交互档超了会"卡"，绘制档超了只是"慢"，所以后者宽松得多。
- 错落封顶：`--m-stagger-max: 6`，`70×6 + 420 = 840ms`。骨架屏行错落放宽到 8 步（它只是呼吸，不参与上限）。
- **不加 `transition-duration` 在布局属性上，一毫秒都不加**（见第 3 节）。
- 时长不随距离缩放：抽屉走 480px 和 toast 走 8px 都用各自档位，不做"距离越远越慢"。
- **改了时长就要查一遍 JS 里的兜底定时器**（见 §0.0 末表）。CSS 动画被 JS 的 `setTimeout` 掐断，
  是"改了时长但看起来没变"的唯一原因。

## 3. 属性白名单

### ✅ 允许 `transition`（可逆状态，必须可中断）

| 属性 | 场景 | 限制 |
|---|---|---|
| `background-color` | 按钮 / 行 / 菜单项 / 导航项 hover、`:disabled` | 只能 120ms `--ease-tog` |
| `border-color` | 输入框、次要按钮、`.mat-thumb` | 同上 |
| `color` | tab 文字、link hover | 同上 |
| `opacity` | `.stat-arrow`、`:disabled`、`.form-err` | 同上 |
| `box-shadow` | 仅 `input:focus` 的 `0 0 0 3px rgba(31,42,36,.06)` 静态环 | 模糊半径 ≤6px，α ≤ .08。**禁止任何"生长 / 扩散 / 发光"阴影** |

### ✅ 允许 `animation`（一次性入场 / 数据入场）

| 属性 | 场景 | 限制 |
|---|---|---|
| `opacity` | 页根、列表项、toast、扇区、骨架呼吸 | 内容类重绘从 `--m-ink-from: .45` 起，不从 0 起 |
| `transform: translateY()` | 页头、下拉菜单（4px） | ≤ `--m-rise`（4px）。**禁止 X 轴位移**（抽屉除外） |
| `transform: translateX()` | 仅 `.drawer`（100% → 0） | 唯一允许的大位移，因为它是"面板移出视野"，不是"元素抖动" |
| `transform: scaleY()` | 仅 2px 发丝（nav 指示器 `.4→1`） | 只允许作用在 1–2px 的线/条上；视觉读作"线在伸长"，不读作"元素放大" |
| `stroke-dasharray` / `stroke-dashoffset` | 折线路径描边生长 | 必须先在 `<path>` 上加 `pathLength="1"`，进度用 0–1 归一 |
| `fill-opacity` / `stroke-opacity` | 环形扇区、折线面积 | 只做淡入，不做色相过渡 |
| `animation-iteration-count` | 骨架呼吸（infinite）、状态点脉动（2 次） | 仅这两处，见第 4.9 / 4.12 |

### ⛔ 禁止被动画（性能 + 视觉双理由）

| 属性 | 为什么 |
|---|---|
| `width` / `height` / `top` / `left` / `right` / `bottom` / `margin` / `padding` / `gap` / `flex-basis` / `font-size` / `line-height` / `letter-spacing` | 每帧触发布局。台账页最窄档一屏 20 行 × 7 列 = 140 个单元格，任何一条布局动画都会把它们全部重算 → 掉帧 + 分线抖动。本项目**没有 FLIP 辅助**（零依赖），改布局属性必然掉帧 |
| `display` | 离散属性，不可能有中间值。不接受"加个类，等 240ms 再用 JS 删元素"的伪退场（时序脆弱、和连点抢跑） |
| `box-shadow` 的模糊/扩散增长 | 与"纸"直接冲突（纸没有光晕），且用户明确否决发光。480px 抽屉的大面积阴影每帧重绘成本很高 |
| `filter: blur()` / `backdrop-filter` | 玻璃拟态，已否决。1080p 全屏 blur 约 1.5–3ms/帧 |
| 整块 `transform: scale()` | Material 的"卡片浮起"语言；更致命的是会 1px 边框压成 0.7px / 拉成 1.3px 发虚 —— 本产品整套视觉都建立在 1px 线上 |
| `transform` 于 `.page` | 它是 `height:100%` 的 flex 容器，还承接 `scrollMap` 的 `scrollTop` 恢复。给它加 transform 会新建包含块、把 sticky 操作条与内层滚动卷进去，收益（4px 位移）远小于风险。页根**只动 opacity** |
| `z-index` / `visibility` 的动画 | 无视觉中间态，只会制造层级闪烁 |
| 任何位移 >6px | 已否决（"位移超过 12px 的入场"为硬约束，本规范自我收紧到 4px） |

**`will-change` 政策**：不预置。仅在 `.drawer` / `.scrim` 打开的那一次动画期间，由 JS 临时加 `will-change: transform` / `opacity`，`transitionend` 后移除。避免 9 个页面长期持有合成层。

## 4. 编排（choreography）

统一记法：`属性：起始值 → 结束值`，`时长`，`曲线`，`delay`。

> **v2 读法**：本节各小节里的时长数字是 **v1 的决策记录**（保留下来是为了说明
> "为什么是这些参数"）。**实际取值一律以 §0.0 的「v1 → v2 数值对照」表为准**，
> 实现代码与 `css/tokens.css` 已按 v2 落地。本节描述的**编排结构**
> （动哪个属性、从什么值到什么值、要不要错落、要不要门控）仍然有效，未变。

### 4.1 路由 / page 切换

**触发条件**：`router.render()` 里新建 `.page`。只在 **path 与上一条 path 不同**时加 `.page--enter`（需要 router 暴露一个 `isRouteChange` 布尔）。同 path 的 `refresh()` / `rerender()`（写操作后重绘）**不加**该标志 —— 否则每审批一条就整页重演一次。

| 对象 | 动效 | 时长 | 曲线 | delay |
|---|---|---|---|---|
| `.page--enter` | `opacity: 0 → 1` | `--t-fast` 120ms | `--ease` | 0 |
| `.page--enter > .page-head` | `transform: translateY(4px) → 0` | `--t-mid` 180ms | `--ease` | 0 |

- **主内容块（`.md` / `.wb` / `.ah-stats` / `.tbl-wrap` / `.detail` / `.pf` / `.md-list`）一律不动。** 整页只留"一层淡入 + 页头一寸落墨"两个动作。给每个卡片块都排一个 40ms 阶梯是最典型的后果——页面读起来像一堆卡片依次飞进来，且总时长会推到 400ms+。
- **不做退场**。`main.innerHTML = ''` 已经把旧 DOM 删除，做退场必须把 router 改成两段式（加 `.is-leaving` → 等 120ms → 清空），等于给每次导航加 120ms 延迟、还要和 `hashchange` 抢时序。而且"我点了导航"这个动作不需要退场来确认。
- 入场必须是**纯 opacity + 布局后位移**：`scrollMap` 的 `scrollTop` 恢复在 `rAF` 里执行，若入场改动高度或产生滚动偏移，恢复值会和动画叠加 → 内容跳一下。
- 页头只位移**不改透明度**：父级已经在淡入，再叠一层透明度会让标题比正文晚亮一档。

### 4.2 主从列表项入场（`.li`）

| 对象 | 动效 | 时长 | 曲线 | stagger |
|---|---|---|---|---|
| `.md-list.is-enter > .li` | `opacity: 0 → 1` | `--t-mid` 180ms | `--ease` | `24ms × k`，`k = min(序号, 5)` |
| `.md-list.is-enter > .lgroup-head` | 同 `.li`，与首项同时 | 180ms | `--ease` | 0 |
| `.empty`（空态） | `opacity: 0 → 1` | 180ms | `--ease` | 0，无 stagger |

- **只做透明度，不做位移**。`.li` 行高 52px、行间只有 1px 分线；逐行 4px 上浮会让相邻两条分线互相追赶（"抽风琴"），且 8 行的位移错开会造成基线错位，字会在动。
- **必须门控（本方案最关键的实现约束）**：`pending.js:87 renderList()` 每次点选都 `innerHTML = ''` 重建。不加门控的结果是：点一条待办，整个左栏重播一次淡入，再点一条又重播 —— 变成"边看边闪"。做法：只在页面 mount 时给 `.md-list` 加 `.is-enter`，用 `animationend`（或一个 >300ms 的一次性 `setTimeout`）移除。切换 tab（请假/续假）视为新数据 → 允许重播一次。
- 最晚结束时间：`k` 上限 5 → `24×5 + 180 = 300ms`，留 20ms 余量（若取 6 步就是 324ms，越界）。第 6 项及以后共用第 5 步的 delay。

### 4.3 表格行 hover / 选中

| 状态 | 动效 | 时长 | 曲线 | 说明 |
|---|---|---|---|---|
| 悬停 | `background-color: transparent → var(--hover)` | `--t-fast` 120ms | `--ease-tog` | **先修 bug**：`.is-hover` → `.is-hover:hover` |
| 选中 | **瞬时**，无过渡 | — | — | 见下 |
| 选中指示条 `td:first-child` 的 `inset 2px 0 0` | **瞬时** | — | — | 保留现状 |

- 选中为什么必须瞬时：`ui.table()` 每次重绘都重建整个 `<tr>`，新节点上类已经存在、没有"上一个值"，**任何 `transition` 都不会执行**。写 `transition: background` 是死代码，还会让人误以为"动效做好了"。
- 如果以后改成"不重建 DOM、只切类"，则升级为：`td` 的 `background-color` 120ms `--ease-tog`；指示条改用 `::before`（2px 宽）+ `scaleY(.35 → 1)` 120ms `--ease`。**现在就别写**，写了不生效。
- 不做逐行 stagger 入场（理由见第 5 节）：台账可能 20 行，逐行错落会把读取推迟到 600ms+，而且筛选/翻页每次都重播。

### 4.4 抽屉 + 遮罩

**结论：240ms 保留不动。** 这是全站唯一的大位移，也是唯一"现有实现就直接可用"的地方。

| 对象 | 打开 | 关闭 |
|---|---|---|
| `.scrim` | `opacity: 0 → 1`，`--t-panel` 240ms，**`--ease-tog`** | `opacity: 1 → 0`，240ms，`--ease-in` |
| `.drawer` | `transform: translateX(100%) → 0`，240ms，`--ease` | `→ translateX(100%)`，240ms，`--ease-in` |

- 遮罩改用 `--ease-tog`（当前是 `--ease`）：`rgba(21,32,46,.18)` 很浅，用强 ease-out 会在开头就逼近终值，读起来是"啪一下变暗"。对称曲线更像"纸面上覆一张描图纸"。
- 抽屉保留 `--ease`：480px 的路程在前 ~90ms 走完约 70%，后段"压住"→ 读作"被推到位"，而不是"滑行"。
- `ui.drawer()` 的 `setTimeout(remove, 260)` **正好**给 240ms 留了 20ms 余量，别改成 240（会砍掉最后一帧）。
- **内容区不做二次入场。** 三条理由：(1) 抽屉 240ms 已经把内容整体带进视野，里面再淡一次 = 让用户在 240ms 之后再等 120ms 才能读；(2) 抽屉是本产品高频动作（看一条 → 关 → 看下一条），每次重播 = 噪音；(3) `.drawer-body` 常是表单，二次淡入会让输入框焦点边框跟着闪一下。
- **唯一例外（内容"新增"而非"进场"）**：`.form-err` 显形 → `opacity: 0 → 1` 120ms `--ease-tog`。它靠 `min-height:16px` 占位，不动高度就不会推挤表单。

### 4.5 toast

| 阶段 | 动效 | 时长 | 曲线 |
|---|---|---|---|
| 进入 | `opacity: 0 → 1` + `translateY(8px → 0)` | `--t-mid` 180ms（原 `.2s ease`） | `--ease` |
| 退出 | `opacity: 1 → 0` + `translateY(0 → 6px)` | `--t-mid` 180ms（原 **350ms，超上限**） | `--ease-in` |

- JS 时序保留：1600ms 打 `is-out`，2100ms 移除 → 500ms 窗口 > 180ms，安全。
- 不加缩放、不弹跳、不加图标转场。toast 是"盖章"，盖完就停。

### 4.6 统计数字（count-up）

**范围**：只做三处 —— `.stat-v`（表格页顶部四格）、`.stat-value > span:first-child`（指标带，**不含** `.stat-arrow` 箭头）、`.ah-stat-value`（管理概览四卡）。

| 参数 | 值 |
|---|---|
| 时长 | `--t-slow` 320ms，**固定**，不随数值大小缩放（10 和 980 都是 320ms） |
| 曲线 | `--ease`（前段冲、后段收，末段慢下来 = "读数落定"） |
| 起始 | 0，整数 `Math.round`，禁止小数/千分位在滚动中出现 |
| 触发 | 只在**首屏 mount**（与 4.1 共用 `isRouteChange`）。任何写操作后的重绘 **直接落终值** |

**硬性前置条件（缺一不可）**
- 三处都已带 `font-variant-numeric: tabular-nums` → 宽度不变，滚动不抖动。**没有 tnum 的地方一律不许 count-up**。
- `.ah-stat-value` 的文本由 `admin.js:133 num()` 生成，**会插千分位逗号**。四位数在越过 1000 时会多出一个字符宽度 → 数字左右跳一格。因此：**只对 `|v| < 1000` 做 count-up，≥1000 直接落值。**
- **不做**：倒计数、数字翻转（flip）、百分比滚动（`.ah-legend-pct` 会在 100% 之前出现 99% 的错值，读者会误读）。
- `prefers-reduced-motion`：现有全局 `.01ms` 规则会让它瞬间完成，效果等价于"直接落值"，无需额外分支。

### 4.7 图表绘制

**现状核对**：折线是 `<path stroke-width="2">`（有 stroke，可以生长）；面积是同形状 `<path fill="url(#gOff|#gOn)">`；**环形图扇区是 `<path fill>`，没有 stroke** → 环形图**不能**用 `stroke-dasharray`，这是两个完全不同的方案。

#### 折线图 `.ah-svg`（方案：描边生长，不用遮罩扫过）

| 对象 | 动效 | 时长 | 曲线 | delay |
|---|---|---|---|---|
| 两条 `stroke` 路径 | 先在 `<path>` 上加 `pathLength="1"`，然后 `stroke-dasharray: 1` + `stroke-dashoffset: 1 → 0` | `--t-slow` 320ms | `--ease` | 线 1：0；线 2：`--m-stagger` 24ms |
| 两个面积路径 | `fill-opacity: 0 → .85`（渐变自身带 stop-opacity，终点别给 1） | `--t-mid` 180ms | `--ease-tog` | 80ms（线先"划"出来，面再"洇"上去）→ 260ms 收 |
| 数据点 `circle` | `opacity: 0 → 1`（**全体同时**，不逐点 delay） | `--t-fast` 120ms | `--ease-tog` | 200ms（线快走完时点才出现）→ 320ms 收 |
| 网格线 / 轴标签 / 图例 | **不动** | — | — | — |

- 三个动作**并行收尾**在 320ms，不是串行相加（串行会变成 320+180+120 = 620ms，严重越界）。面和点的 delay 是编排常数，只此一处用，不建变量。

- `pathLength="1"` 是关键：不用 `getTotalLength()`、不用 JS 量长度，纯 CSS 就能跑，Chrome/Safari/Firefox 均支持。
- **明确否决"遮罩扫过"**：需要额外一个 `<clipPath>` + 一个跟随移动的 `<rect>`，等于每帧重算裁剪；而 `<svg viewBox="0 0 420 190">` 是等比缩放的（`preserveAspectRatio`），裁剪宽度和实际像素不对齐，窗口一缩放就得重算。在一个零构建项目里，这条路的维护成本远高于收益。
- 数据点逐个 delay 也不行：7 个点 × 24ms 会把总时长推到 320ms 之外。

#### 环形图 `.ah-donut-svg`（方案：分段落墨，不用旋转扫过）

| 对象 | 动效 | 时长 | 曲线 | stagger |
|---|---|---|---|---|
| 各扇形 `<path>`（按绘制顺序） | `opacity: 0 → 1` | `--t-mid` 180ms | `--ease-tog` | `24ms × k`，k ≤ 3（最多 4 段：`72 + 180 = 252ms`） |
| 中心"总计"数字 | count-up，规则同 4.6 | 320ms | `--ease` | 0 |
| 图例 `.ah-legend-row` | 不动 | — | — | — |

- 读感是"套色印刷一段一段盖上去"，符合纸感；而且每段都是满色出现，中途不会出现"半片饼"。
- **明确否决"旋转扫过"（conic mask / 旋转 clip）**：扇区是 `A` 弧命令按数据累加生成的，做扫过要再造一个同半径遮罩扇形并精确对齐 `large-arc-flag`，还要处理各浏览器 `mask` 的 `objectBoundingBox` 差异。中途会露出"半片饼"，视觉上像加载失败。
- 一次性门控同 4.1：`shell.rerender()` 会整页重建，不门控的话每审批一条折线就重画一遍。

### 4.8 下拉菜单 `.dd-menu`

| 阶段 | 动效 | 时长 | 曲线 |
|---|---|---|---|
| 打开 | `display` 瞬时切 `block`，同时 `opacity: 0 → 1` + `translateY(-4px) → 0`，`transform-origin: top right` | `--t-fast` 120ms | `--ease` |
| 关闭 | **瞬时** `display:none`，无退场 | — | — |
| 菜单项 hover | `background-color` | 120ms | `--ease-tog` |

- 关闭必须瞬时：下拉是"我现在就要它消失"，240ms 退场会让人觉得点击没生效（连点两次时尤其明显）。
- 不做 `scaleY` 高度展开（176px 宽的菜单做"长出来"是桌面端不该有的手势，且会把 1px 边框压成亚像素）。
- `.dd-menu` 现有 `box-shadow: none` —— 不要为了"浮起感"加阴影动画。

### 4.9 骨架屏 shimmer（`.sk`）

**前提：只在加载超过 400ms 时出现。** 数据走 `api.loadStore()`（本地/内网，通常 <200ms）。若不加延迟判断，会出现"白块闪一下" —— 比直接出现更糟、更像卡了。落地：首次取数 `setTimeout(400)` 后插入 `ui.skeletonRows()`，同步命中则不出现。

| 参数 | 值 |
|---|---|
| 做法 | **不做亮白扫光**。改用"纸的呼吸"：`.sk-bar` 的 `background-color` 在 `--m-sk-a: #F1F6EC`（= `--paper-2`）与 `--m-sk-b: #E7EEDF` 之间往返 |
| 周期 | `--m-sk-cycle: 1.8s`，`animation-direction: alternate`，`--ease-tog`，`infinite` |
| 行错落 | `animation-delay: 24ms × k`（k ≤ 6），避免整片同步 —— 整片同步更像"故障闪烁" |
| 结束 | 内容挂载即移除整个 `.sk`，**无淡出**（骨架→内容交叉淡出需要同时保留两份 DOM，必然有一帧半透明重叠） |
| reduced-motion | 静态 `--paper-2`，不呼吸 |

- 为什么不用白色高光扫过：那是"流光/玻璃"的语言，在米绿纸上会出现一条比卡片还亮的带子，直接破坏纸感。
- 对比度控制：两端同色阶，ΔL ≈ 3%，弱于 1px 的 `--line`(#E6EBE0)。读感是"没印实的浅色块在纸面下微微起伏"，不是"闪烁"。
- **这是全站唯一允许 `infinite` 的地方**，且它被加载态约束（数据到达即消失），不属于"无限循环的装饰动效"。

### 4.10 侧栏导航选中指示器

- **先补基础规则**：`.nav-item.is-on::before` —— 2px 宽、`left: 0`、`inset-block: 8px`、`background: var(--ink)`。这与 `.li.is-on::before`（2px 墨线）是同一套视觉语言，不是新发明。`layout.css:162` 的 `top/bottom: 6px` 覆写才有意义。
- 动效：`transform: scaleY(.4) → 1` + `opacity: 0 → 1`，`--t-mid` 180ms，`--ease`，`transform-origin: center`。只在这条 2px 发丝上做 scaleY —— 视觉读作"线在伸长"。
- **已知副作用（必须写进 CSS 注释）**：`renderNav()` 在每次 `shell.sync()` / `setScope()` 后重建整个 nav，新节点上类已存在 → 这段 animation 会在**每次审批后重播一次**。两个选择：
  - A（推荐）：接受它。2px 发丝、180ms，几乎不可察觉，且它恰好是"焦点回到了当前页"的提示。
  - B：退化为纯 `opacity: 0 → 1` 120ms（更轻），或干脆瞬时。
  - **不要**为了"只播一次"给 nav 加跨渲染状态位 —— 代价大于收益。
- `.nav-item.is-on` 的底色 `--sel` 出现：瞬时（新节点，没有可依赖的过渡）。

### 4.11 按钮按下 / 危险操作（驳回）

| 对象 | 动效 | 参数 |
|---|---|---|
| `.btn:active` | `transform: translateY(1px)`，**瞬时**（不加 transition） | 保留现状；`scale(.98)` **禁止** |
| 按钮 hover | `background-color` / `border-color` | 120ms `--ease-tog`（现有 `--t-fast --ease` 只换曲线） |
| `:disabled` | `opacity .38` | 120ms `--ease-tog`（提交中 / 未填原因时的"确认驳回"） |
| 驳回成功后 | ① `toast('已驳回')` 180ms 淡入；② 该条移出列表 → 下一条被选中 → 右栏 `.detail` 重新落墨 120ms（`.45 → 1`）；③ tab 计数与侧栏 badge **瞬时**更新 | — |

- **没有抖动、没有红闪、没有脉冲。** 驳回是不可逆的严肃动作，动效在这里只能承担"确认它发生了"。抖动/闪红是制造焦虑，而且会把"红色"从**状态语义**降级成**装饰语义**（一旦红色会闪，它就不再专指逾期）。
- `.reject-panel` 显出：现在靠 JS 换 DOM。若要动，只允许 `opacity: 0 → 1` 120ms `--ease-tog`，**不动高度** —— 它不是"从某处长出来"，而是"显影"。

### 4.12 状态点脉冲（严格限量）

**允许，但条件是窄的。** 默认全站静止：不写 `.status i { animation }`，而写 `.is-urgent .status i` —— 把"要不要脉冲"变成显式类，谁加谁负责。

| 条件 | 值 |
|---|---|
| 允许的位置 | ① 详情页状态行（`.detail` / `.app-detail` 内，单条记录）；② 提醒卡里**最新一条** `.ah-alert-dot--danger`（需 JS 打 `.is-urgent`） |
| 允许的状态 | 只是 `逾期`（`data-tone="red"`）与"待审批超 24h"（`.li-wait.is-red`），且同时只允许 1 个实例 |
| 动什么 | 只动 `opacity: .35 → 1 → .35` |
| 周期 / 次数 | `--m-pulse-cycle: 1.2s`，`iteration-count: 2`（`--m-pulse-times`），2.4s 后停在 1 |
| 禁止 | `box-shadow` 扩散（= 发光，已否决）；`transform: scale`（呼吸灯/心跳是消费级语言）；表格 `td` 内的 `.status i`；`.li-wait` 列表内；侧栏 `.count--alert` |
| reduced-motion | 全局 `.01ms` 规则会让它瞬间跑完 2 次后停在终值 1 —— 正好是期望结果，无需额外规则 |

台账一屏 20 行 = 20 个点在闪，等于没有信息。脉冲是"指路"，不是"装饰"，一屏只能有一个路标。

### 4.13 焦点与输入（补充）

- `input:focus` 的 `box-shadow: 0 0 0 3px rgba(31,42,36,.06)`：120ms `--ease-tog`（保留现状，只换曲线）。
- `::focus-visible` 的 `outline: 2px solid`：**不参与任何动画**。焦点环必须第一帧就完整可见（可访问性硬要求）。
- 输入框 `is-saving / is-saved / is-err` 的边框色切换：120ms `--ease-tog`，只动 `border-color` 与那个 2px 静态环。

## 5. 禁止动效清单（这个产品里不该动的）

| 禁止 | 为什么 |
|---|---|
| 卡片 hover 抬升 / 放大 / 阴影加深 | Material elevation，与"纸"直接冲突；用户已否决发光与 >16px 的大圆角路线，抬升是同一族语言 |
| 表格行逐行 stagger 入场 | 20 行 × 24ms 会把读取推迟到 600ms+（违反"禁止延迟信息读取"），且筛选/翻页每次都重播 |
| 页面退场 / 新旧页交叉淡出 | router 已清空旧 DOM；两段式会给每次导航加 120ms 延迟并与 `hashchange` 抢时序 |
| 骨架屏 >400ms 即出 / 亮白扫光 | 白块闪一下比空白更糟；高光扫过 = 流光语言 |
| 数字滚动用于会变动的计数（tab 计数、侧栏 badge、`rerender()` 后的统计） | 每点一次就滚一遍，把"结果"变成"过程" |
| 百分比 / 小数 count-up | 越过 100% 前会出现 99% 的错值；千分位会插字符导致宽度跳 |
| 环形图旋转扫过 / 遮罩扫过 | 中途露出"半片饼"像加载失败；跨浏览器 mask 对齐脆弱 |
| 图表 hover 时重绘 / tooltip 跟随 | 数据已读完，重画只会干扰；重绘成本高 |
| 表格内多实例状态点无限脉冲 | 一屏 20 个点在闪 = 无信息 |
| 侧栏图标 hover 旋转 / 弹跳 | 文具不动。图标动 = 玩具 |
| 下拉菜单 `height` 展开 / `scale` 弹入 | 会压坏 1px 边框；桌面端不该有"长出来"的菜单 |
| 按钮按下 `scale(.98)` / 位移 >1px | Material 按压语言；且行高只有 36px，位移会和相邻元素打架 |
| 驳回等危险操作的抖动 / 红闪 | 制造焦虑，并把红色从状态语义降级为装饰语义 |
| 状态色做 hue 过渡（琥珀 → 红） | 过渡中会经过一个被读成"第三种状态"的中间色 |
| 滚动触发 reveal（IntersectionObserver） | 9 个页面、滚动容器是内层 pane，需要额外 JS 与 per-page 逻辑；最大风险是首屏内容被藏起来 = 直接违反"不许延迟读取" |
| toast / 弹层从底部弹入 + 回弹 | spring 语言，已否决 |
| 焦点环生长动画 | 可访问性：焦点必须立刻可见 |
| 无限循环的装饰动效（呼吸、漂浮、闪烁、渐变流动） | 已明确否决。唯一例外：骨架屏（受加载态约束）与状态点脉动（2 次即停） |
| `filter: blur()` / 玻璃拟态 / 紫色渐变光斑 | 已明确否决 |
| 任何 `width/height/top/left/margin/padding` 的动画 | 触发布局，见第 3 节 |

## 6. 变量表（追加到 `css/tokens.css` 的「形状与动效」段）

命名沿用现有风格：时长 `--t-*`、曲线 `--ease*`、动效专用常量 `--m-*`。动效变量与 `--fs` 字号系数无关（不做字号动画），但**所有毫秒值必须走变量，页面里不允许出现裸的 ms 值**。

```css
  /* ---- 形状与动效 ---- */
  --r: 8px;
  --dot: 6px;
  --bar-band: 4px;
  --bar-compare: 6px;

  /* 时长阶梯（v2）：交互档上限 560ms，数据绘制档 900ms、总收尾 ≤1.2s */
  --t-fast: 160ms;     /* 微反馈：hover / active / 焦点 / 禁用态。再慢会"粘" */
  --t-sel: 220ms;      /* 状态切换：底色 / 边框色 / 颜色，来去同速 */
  --t-fade: 300ms;     /* 内容淡入：页根、.detail 重新落墨 */
  --t-mid: 420ms;      /* 元素级进出：列表项入场 / toast / 页头落墨 / 下拉展开 */
  --t-panel: 560ms;    /* 面板级：抽屉 / 遮罩 */
  --t-slow: 900ms;     /* 数据绘制：数字滚动 */
  --t-draw: 900ms;     /* 数据绘制：折线描边生长 */
  --t-draw-area: 700ms;/* 折线面积上彩 */
  --t-draw-seg: 620ms; /* 环形图单段落墨 */

  /* 缓动：4 条封顶。禁止 spring、禁止 linear() 自定义时间函数 */
  --ease: cubic-bezier(.2, .8, .25, 1);     /* 入场 / 展开（快起慢收，笔尖落纸） */
  --ease-in: cubic-bezier(.4, 0, 1, 1);     /* 退场（加速离开，尽快把注意力还回去） */
  --ease-tog: cubic-bezier(.4, 0, .6, 1);   /* 状态切换（对称、可中断、来去同速） */
  --ease-draw: cubic-bezier(.32, 0, .18, 1);/* 数据绘制（起手慢、中段匀、收尾缓，像笔在走） */

  /* 动效常量 */
  --m-rise: 4px;         /* 入场位移上限。硬约束：任何入场位移 ≤ 6px，本规范收紧到 4px */
  --m-stagger: 70ms;     /* 统一错落间隔：列表 / 骨架行 / 环形扇区都用它 */
  --m-stagger-max: 6;    /* 文档常量，不要写进 CSS。错落封顶步数：70×6+420=840ms */
  --m-ink-from: .45;     /* 内容"重新落墨"的起始不透明度。不从 0 起 —— 保证全程可读 */

  /* 折线图编排：线 → 面 → 点，依次入场、末尾对齐（≈1.02s 收尾） */
  --m-delay-area: 280ms;
  --m-delay-dots: 760ms;
  --m-draw-dots: 260ms;
  --m-draw-stagger: 150ms;/* 环形扇区错落 */

  /* 纸感材质：骨架屏呼吸（唯一允许 infinite 的动效，受加载态约束） */
  --m-sk-a: #F1F6EC;     /* = --paper-2，呼吸亮端 */
  --m-sk-b: #E7EEDF;     /* 呼吸暗端，与亮端同色阶，ΔL≈3%，弱于 1px 的 --line */
  --m-sk-cycle: 2.4s;    /* 呼吸周期；alternate + ease-tog */

  /* 状态点脉动：仅 .is-urgent 单实例，2 次即停 */
  --m-pulse-cycle: 1.5s;
  --m-pulse-times: 2;    /* animation-iteration-count，单位无关数字，可直接用 */
  --m-pulse-min: .35;    /* 最低不透明度。禁止低于 .35：再低会被读成"点消失了" */
```

> 这张表与 `css/tokens.css` 的实际内容逐行对应。改时长时**两边一起改**，
> 并且回头查一遍 §0.0 末表列的 JS 兜底定时器。

## 7. 验收清单（落地后逐条过）

> **v2 改了验收方式**：光看最终截图验不出快慢（终态永远一样）。
> 必须用 `scripts/motion_frames.js` 逐帧取证 —— 拆掉门控重放一次，
> 按 120/320/560/820/1200ms 拍下来，用画面证明"看得见"。

1. **节奏（v2 新增，最高优先）**：`node scripts/motion_frames.js outputs/frames`，
   逐帧看：120ms 时数字还在中途、折线只起笔、轮盘几乎空白；320ms 画到八成；
   560ms 面积洇开；820ms 数据点落位。**若某一帧已经全是终态，说明那一档又快了。**
2. **时长**：交互档任何单次动画 ≤560ms（含 delay）；数据绘制总收尾 ≤1.2s。
3. **定时器没被截断**（v2 新增）：抽屉关闭到节点消失 ≈620ms；列表门控摘类 ≈1400ms；
   toast 淡出到移除 ≈2300ms。**改时长后必须重新核对这三条**。
4. **布局**：动画期间 Layout 次数为 0（只应有 Paint / Composite）。
5. **重播**：连续点 10 条待办 —— 左栏不应重播淡入；连续审批 3 条 —— 折线图不应重画、nav 指示器最多轻微重播。
6. **可读性**：`.detail` 重绘过程中正文始终可见（不出现"整块消失再出现"）。
7. **慢网**：断网络节流到 3G，骨架屏只在 >400ms 后出现，且不闪。
8. **reduced-motion**：系统开启"减少动态"后，所有页面内容完整可见、无位移、数字为终值、骨架静止。
9. **无裸值**：`grep -rn "ms " css/` 只应命中 `tokens.css` 的变量定义。
10. **无禁用项**：`grep -rn "scale(\|blur(\|backdrop-filter\|width .*transition" css/` 只应命中 `scaleY` 那一处。
